# Changelog

- **New (native signing, agent side):** `Atlas\Pca\Sign`, `KeyPair`, `Agent` (`src/Agent.php`), the producer half of the package, so an agent never needs a TypeScript process: `KeyPair` (libsodium Ed25519), `Sign::mintGrant` (envelope, salted goal commitment, `holder_pq`), `Sign::delegate` (append-only caveats; `sealedCaveat`, `maxUsesCaveat`, `needsDischargeCaveat`), `Sign::commitPlan` with Merkle proofs, `Sign::buildPcactn` (signed `aud`/`iat`/`exp`/`nonce`, optional signed slots), `Sign::headers`, `signEscalationAnswer`, `signDischarge`, `signNarrow`, `issuePassport` / `signPassport`, `signWorkflow` / `signStepReceipt`, `signReadGrant`, `signAggregateGrant`, `signFreshAt` and the `Agent` client (`act`, `delegate`, `usePlan`: counter, nonce and header handling). ML-DSA-65 / 87 and SLH-DSA-SHA2-128f / 256s and their hybrid and nested-hybrid suites sign through OpenSSL >= 3.5 libcrypto over FFI (`PqKeyPair`, the same binding the verifier uses; PHP's own `openssl_*` functions expose none of these key types); without the FFI extension or OpenSSL 3.5, and for FN-DSA and LESS, asking to sign throws `UnsupportedSigner` (`unsupported_suite: <alg>`). Deterministic outputs reproduce `producer-vectors.json` byte for byte (`tests/AgentProducerTest.php`, which also round-trips every artifact through the verifiers).

- **Breaking** (K5, `plan_root_authorized` default-deny): a verifier with no plan source (`plan: null`, no `plans` registry, no `context.plan`) no longer reports `plan_root_authorized` as `not-enforced`; the check FAILS with `plan_root_authorized: default-deny: no authorized plan is configured for this verifier (supply the plan and its authorization, or set insecureSkipPlanRootCheck)`. The `insecureSkipPlanRootCheck` opt-out of the lower-level verifiers in the other SDKs does not exist here: `Authorize::authorize` requires `plan_root_authorized` to pass and never accepts it.
- Add (K5, workflow and read-side authorization; additive): `Workflow` admits one step of a principal-signed workflow DAG (`admitStep`, `bindPromises`, `planRootAuthorized`, `validWorkflowBody`, `dagError`, `workflowDigest`, `receiptRef`, `valueDigest`): dataflow edges with integer relations, label (taint) restrictions, freshness, cost budgets and the signed receipt chain, with promise pipelining that escalates when unconstrained. `ReadSide` applies a signed read grant to one response (`redactRead`: shown / masked / dropped per data class, tighten-only, enumeration caps), verifies read-receipt chains (`readChainLabels`) and gates a sink on the labels read (`checkSink`). Both are total (a thrown error is a denial) and integer-only (`2500.0` is not an integer). Replayed against `workflow-vectors.json` and `readside-vectors.json` by `php conformance-vectors.php workflow readside` and PHPUnit.
- Add (K5, workflow through `PcaMiddleware`; additive): `AuthorizeOptions` takes `workflow` (same shape as `Authorize::authorize`) and `workflowCall` (`(ServerRequestInterface): array|Obj|null`; default: the JSON body member `workflow` when the PCActn itself came in the body, else none). Required and no step is a 403 before the PCActn is decoded; a throwing reader is a 403 (`workflow: error (fail closed)`). Tests: `PcaMiddlewareWorkflowTest`.
- Fix (K5, workflow gate order): a call carrying a workflow step with an undecodable or absent PCActn is no longer judged by the gate; the pipeline's refusal stands, now `401` check `pcactn`, reason `undecodable PCActn: could not be decoded` (was check `wire`, `wire: PCActn could not be decoded`). An absent PCActn stays `wire: no PCActn presented`.
- Add (K5, workflow admission in `authorize` and the tokenisation vault; additive): `Authorize::authorize` takes optional `workflow` (`['principal', 'rsSigner', 'required' => false]`, the keys this server pinned) and a per-call `workflowCall` (`commitment`, `receipts`, `step`, `units`, `goal_digest`). When configured, `Workflow::admitStep` decides the call BEFORE verification and replay (a refusal never consumes the PCActn's counter): no step and `required` refuses `workflow: this call carries no workflow step (fail closed)`; a step that is not admitted refuses 403 with `checks = {workflow: fail}` and reason `workflow: <code> (step <id>)` (`decision` is `escalate` for an escalating admission). `ReadVault` adds `redactReadWithVault` / `detokenize` over a `VaultStore` (`MemoryVault`), the verification-only aggregate grant, `aggregateRead` (k-anonymity floor, clamp, query cap, integer micro-epsilon budget, repeat queries free) and the integer-exact discrete Laplace sampler (`seededDraws`, `secureDraws`, `discreteLaplace`; `secure` is the production noise mode). Replayed against `vault-aggregate-vectors.json` and `authorize-workflow-fixtures.json` by `php conformance-vectors.php vault-aggregate authorize-workflow` and PHPUnit.
- Add (K9): offline Sigstore bundle verification, `Atlas\Pca\SigstoreBundle` (`parseTrustedRoot`, `verifyCore`, `verify`; the openssl extension and sodium, there is no PHP Sigstore library). A port of the TypeScript reference: bundle v0.2 / v0.3 with a DSSE in-toto statement, Rekor v1 `dsse` 0.0.1 / `intoto` 0.0.2 and Rekor v2 `hashedrekord` 0.0.2 entries, RFC 3161 timestamps and the Rekor v1 SET as time sources, RFC 9162 inclusion to a signed-note checkpoint, the Fulcio path at every verified time, the embedded SCT, identity from the certificate extensions. `verify` returns the SLSA v1 facts (an `Obj`) `ProvenanceGate::gate` checks. Never throws on a bundle. Vector family `sigstore` replays `sigstore-vectors.json` (`php conformance-vectors.php sigstore`).

- **Breaking** (action kit, "unconfirmed means maximally dangerous"): `Actions::traitsOf` / `Actions::effective` now return the top of the registry (every trait id, core and custom) for any def without a valid signed confirmation by a key pinned with the `reviewer` role; `review.state: authored` no longer counts. New optional `?Obj $pins` argument on `effective`, `traitsOf`, `schemaVerbFloorError`, `schemaFloorError` and `ActionsRegistry::rule22Integrity`; `effective` also returns `confirmed`. Add `Actions::reviewerPinsError`, `reviewMessage`, `isConfirmed`, `verbConfirmationError`, `hintTraits`, `topTraits`. An unconfirmed schema verb must carry every registry trait (`schema_traits_forged`). v2 schema verbs may carry a `confirmation` (`IntentV2::confirmationShapeError`); `actionSchemaShapeError` takes `$signed = true`. New `schema_shape` vector kind.

- Add (action kit registry layer): `ActionsRegistry` and `PackTracker` verify signed evolution records, principal re-approvals, grant pins (exact, pack or chained evolution), signed and sharded packs, pack inclusion proofs and rule 22 over a whole v2 document; the shared vectors replay byte for byte.

- R4-01: `Pca::verifyChain` now takes the root's PQ authority from the verifier, exactly like the TypeScript reference (R3-01).
